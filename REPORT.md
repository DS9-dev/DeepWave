# Отчёт: эксперимент с API Яндекс Музыки, жанр Rock

Запуск 20.10.2026 · `yandex-music` 3.2.2 · Python 3.10.11 · ошибок: 0

## 1. Авторизация
- OAuth Device Flow (`client.device_auth`): пользователь вводит код на сайте Яндекса, логин и пароль скрипт не видит.
- Токен сохранён в `%USERPROFILE%\.yandex_music_token.json`. В лог и результаты он не попал.
- Подключение подтверждено через `client.me`: аккаунт получен (uid, логин, имя), подписка Плюс активна.

## 2. Жанры
- `client.genres()` вернул 36 жанров верхнего уровня.
- Важно: на верхнем уровне жанр называется **`allrock`** («Рок»). Жанр **`rock`** означает «Иностранный рок» и вложен в `allrock`. Рядом лежат `rusrock`, `hardrock` и т. п., а `metal`, `punk`, `alternative`, `indie` вынесены на верхний уровень как отдельные жанры.
- У `rock` нет своих поджанров. Скрипт проверял принадлежность только к `rock` и поэтому слишком строг: например, `rusrock` и `hardrock` он не засчитывает.

## 3. Полученные треки (жанр `rock`)

| Источник | Метод API | Треков | Жанр альбома = rock |
|---|---|---|---|
| Жанровое радио | `rotor_station_tracks("genre:rock")` | 29 | 29/29 (100%) |
| Жанровая страница | `metatag_albums("rock", sort_by="popular")` → `albums_with_tracks` | 50 | 50/50 (100%) |
| Текстовый поиск «rock» (для сравнения) | `search("rock", type_="track")` | 20 | 1/20 (5%) |

Для каждого трека есть: `track_id`, название, исполнители и их id, альбом и его id, год, жанр альбома, у радио также жанры исполнителей. Все записи лежат в `results/rock_tracks.csv` и `rock_tracks.json`.

Примеры с радио: The Rolling Stones — Gimme Shelter, Lynyrd Skynyrd — Born to Run, The Stone Roses — Beautiful Thing.
Примеры с жанровой страницы: Nirvana, Queen, Red Hot Chili Peppers, Bon Jovi, Evanescence, Imagine Dragons.

## 4. Связаны ли треки с жанром на самом деле
- **Да, для радио и жанровой страницы.** Обе выдачи строятся по жанру на стороне Яндекса, а не по тексту: у 100% треков в метаданных альбома стоит `genre = "rock"`. У 28 из 29 треков радио жанр `rock` есть и у исполнителя.
- **Нет, для текстового поиска.** Он находит треки со словом «rock» в названии: house, рэп, поп, индастриал и т. д. Только у Queen — We Will Rock You жанр альбома `rock`. Этот способ для выборки по жанру не подходит.
- Нюанс: у Яндекса жанр задаётся на уровне альбома (и исполнителя), а не трека. Отдельного жанра у трека в API нет.

## 5. Ограничения и наблюдения
1. **Радио не листается страницами.** Треки приходят порциями по ~5 штук, следующая порция запрашивается через `queue=<последний трек>`. Без отправки событий прослушивания станция начинает повторяться. Получили 29 уникальных треков за 24 секунды, после чего скрипт остановился на повторах. Выдача зависит от пользователя и меняется от запуска к запуску.
2. **Жанровая страница даёт альбомы, а не треки.** Нужен отдельный запрос на каждый альбом. Встречаются дубликаты: один трек в разных изданиях или сборниках (Queen, Nirvana, Bon Jovi), поэтому нужна дедупликация по `track_id`. В эту выдачу попадают и малоизвестные релизы с жанром `rock` (ИСАЙЯ, KSB muzic, СДП).
3. **У треков из `albums_with_tracks` нет жанров исполнителей.** Проверка возможна только по жанру альбома.
4. **Модели библиотеки расходятся с ответами API.** Для `/genres` библиотека предупредила об отсутствии обязательного поля `Genre.images`. В 3.2.x это только предупреждение, работа не прерывается.
5. **API неофициальный.** Он не документирован Яндексом. Библиотека входит от имени официального Android-клиента (его публичный `client_id`). Ответы могут меняться без предупреждения.
6. Токен библиотека сама не обновляет. Хранение и обновление токена — задача вызывающего кода.

## 6. Что поправить в следующем шаге
- Считать жанровым семейством всё дерево `allrock`, а не только `rock`. Возможно, использовать `genre:allrock`, если нужен «рок вообще», а не только иностранный.
- Убирать дубликаты в выдаче жанровой страницы.
