# Отчёт 2: глубина каталога, жанр allrock

Источник данных: `results_depth/allrock` (прогон 20.10.2026: 564 запроса, 7,3 мин, без ошибок и без отказов API).
Все цифры ниже получены из собранных файлов. Отдельно помечены оценки.

## Главный вывод

**Полный обход жанра реален, если идти через исполнителей, а не через жанровые подборки.**
`artists_tracks` отдаёт **весь** список треков исполнителя: у 75 из 76 обработанных исполнителей число полученных треков совпало с `pager_total` (последнего оборвал лимит запросов). Это 1–4 запроса на исполнителя, по ~64 новых трека на запрос, без падения к концу прогона.
Узкое место — **находить самих исполнителей**. Жанровые страницы показывают только верхушку, поэтому исполнителей нужно накапливать обходом похожих исполнителей и лейблов.

## 2. Есть ли исчерпание
- **Дискографии: нет.** Прирост по четвертям прогона — 72 / 65 / 57 / 66 трека на запрос. Он ограничен только числом известных исполнителей.
- **Похожие исполнители: нет.** Пройдено 2 уровня от 10 стартовых исполнителей. На каждый запрос — ~9,7 новых рок-исполнителей, очередь растёт.
- **Радио: да.** Уже после 12-й порции почти всё повторяется: 300 полученных треков дали 125 уникальных.
- **Жанровые страницы: искусственный потолок.** API сообщает, что в жанре ~1 000–11 000 альбомов (`pager_total`), но реально отдаёт 100–200 альбомов на поджанр, дальше приходит пустая страница. Сортировка `new` вернула те же альбомы, что и `popular`: 0 новых на первой странице. Исполнители жанра отдаются тоже только первыми 50–150 позициями.

## 3. Полнота охвата
*Оценка.* Сумма `pager_total` по 12 поджанрам — около **69 000 альбомов**. Это нижняя граница: у пяти поджанров total подозрительно близок к 11 000, похоже на ограничение счётчика. Найдено **3 090 альбомов (≈4,5%)** с ~34 800 треками.
- Исполнителей с жанровым тегом рока найдено **1 854**. Счётчик исполнителей жанра в API — ≥11 000 (снова похоже на ограничение счётчика). Значит, найдено около **≤17%** исполнителей.
- Полностью обработано только **76** дискографий (<1% исполнителей жанра).
- По годам найденные альбомы смещены к новым: 2020-е — 1 179, 2010-е — 949, 1990-е — 240, 1970-е — 90.

## 4. Почему 27% треков «не Rock» и насколько надёжна проверка
Проверка сравнивает **жанр альбома** с деревом `allrock` из 13 поджанров. Причины расхождений:
1. **Соседние жанры у Яндекса — отдельные ветки.** Alternative, metal, punk, indie, alt-metal, nu-metal не входят в `allrock`. В плейлистах «рока» это половина «чужих» треков: alternative 491, alt-metal 112, punk 107, metal 97…
2. **Нерок-альбомы рок-исполнителей.** В дискографиях «чужие» треки — это pop 415, alternative 369, folk 135 и т. д. Ещё сюда попадают треки, где исполнитель только приглашён, — `artists_tracks` их тоже возвращает.
3. **Пустой жанр альбома** — 222 трека.

Вывод: жанр альбома — надёжный, но **узкий** критерий. Что считать «роком», должен решать пользователь — например, `allrock` + alternative + punk + metal. Тег исполнителя подходит как запасной признак, но он размытый.

## 5. Скрытые перекосы
- **Стартовые точки популярные.** Жанровые страницы отдают только верхушку: медианные лайки альбома — 226, лидеры — Elvis Presley (35 альбомов), Нервы, Scorpions. У альбомов из лейблов медиана 86 лайков, 52% — синглы, это заметно глубже. Обход через похожих наследует популярность стартовых исполнителей. Малоизвестные исполнители могут быть слабо связаны с графом, поэтому нужен второй вход через лейблы.
- **Внутри исполнителя перекоса нет.** 85,5% треков из дискографий стоят дальше 20-го места в популярности исполнителя. Доля рок-треков одинакова на всех местах: 77% в первой двадцатке, 76–84% дальше. Редкие песни известных групп доступны полностью.
- **Плодовитые исполнители доминируют.** 40 исполнителей с более чем 50 треками дают **73%** рок-треков. Рекорд — Little Richard, 651 трек. При случайном выборе из треков такие исполнители забьют эфир. Значит, случайный выбор нужен **сначала по исполнителю, потом по треку**.
- **Повторы версий.** У 7,2% рок-треков встречается то же название у того же исполнителя: живые версии, ремастеры, сборники. Нужна нормализация по «исполнитель + название». `artists_tracks` уже частично склеивает версии: у Queen 270 треков против 858 в сумме по альбомам, у Kiss 312 против 1 216.

## 6. Ограничения API
- Глубина жанровых страниц ограничена ~100–200 альбомами и 50–150 исполнителями на поджанр. Сортировка `new` не дала других альбомов.
- `artists_direct_albums` ограничен 100 альбомами за запрос. Не критично: `artists_tracks` полнее.
- Лайки исполнителя в этих ответах не приходят: 0 из 4 635. Популярность трека можно оценить только по его месту в списке исполнителя, по `bests` альбома (у 1 881 альбома) и по лайкам альбома (у 2 936).
- Лимитов частоты за 564 запроса не встретилось. Скорость — ~0,5–0,7 с на запрос. Нагрузку в тысячи запросов пока не проверяли.

## 7. Можно ли пройти большую часть каталога
*Оценка.* Около 2–3 запросов на исполнителя: 1–4 страницы треков плюс 1 запрос похожих. Для ~11 000 исполнителей жанра это **~25–35 тыс. запросов, ~4–6 часов**. Работу можно делать порциями с продолжением с места остановки и с паузами. Большая часть времени уйдёт на поиск исполнителей.

## Следующий эксперимент (предложение)
**«Обход по исполнителям с продолжением»** — только сбор, без плеера:
1. Сохранять очередь исполнителей и обработанных в простой файл, чтобы следующий запуск продолжал с места остановки.
2. Источники исполнителей: жанровые страницы (старт) + похожие + лейблы. Для каждого нового исполнителя — полный `artists_tracks`.
3. Бюджет — ~1 500 запросов за запуск. Измерять, падает ли со временем приток новых исполнителей, какую долю дают лейблы, сколько исполнителей находится только через лейблы, сколько у них лайков.
4. Попутно дешёвая проверка обхода потолка жанровых страниц: параметр `period`, другие значения `sort_by`, `page` вместо `offset`.
5. Состав жанра задаётся списком: `allrock` + выбранные соседние жанры.

Текущие скрипты (`rock_probe.py`, `catalog_depth.py`) не менялись.
