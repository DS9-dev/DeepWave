# crawler.py — накопительный сбор каталога DeepWave

Каталог хранится в одном файле `catalog\<жанры>.sqlite` и растёт от запуска к запуску.
Остановить сборщик можно в любой момент, при следующем запуске он продолжит с того же места.
Токен берётся через `ym_auth.py` (зашифрованный `%USERPROFILE%\.yandex_music_token.dpapi`, тот же, что у DeepWave) и нигде не выводится.

## Команды (PowerShell)

```powershell
cd "<папка проекта>"

python crawler.py run                          # короткий сбор: 300 запросов (~5 мин)
python crawler.py run --max-requests 1500      # эксперимент: ~25–35 мин
python crawler.py run --max-minutes 120 --max-requests 100000   # длительный сбор по времени
python crawler.py status                       # что собрано, по запускам
python crawler.py export                       # CSV в catalog\allrock_export\
python crawler.py genres                       # все id жанров
```

**Остановка:** `Ctrl+C` один раз — сборщик закончит текущую задачу, сохранит её и выйдет.
`Ctrl+C` второй раз — выйдет сразу; незаконченная задача откатится и повторится при следующем запуске.
**Продолжение:** та же команда `run`. Уже обработанные исполнители, лейблы и страницы повторно не запрашиваются.

**Другие жанры** (каждый набор жанров — свой каталог):
```powershell
python crawler.py run --genres allrock,alternative,punk,metal,indie --catalog rock_wide
python crawler.py status --catalog rock_wide
```
Каждый id берётся вместе со всеми поджанрами.

## Как работает
- **Старт:** жанровые страницы всех поджанров (альбомы и исполнители) и общие новинки Яндекса, из которых отбираются альбомы нужных жанров. Новинки обновляются раз в сутки.
- **Расширение** идёт по кругу из задач трёх типов:
  - полная дискография исполнителя (`artists_tracks`, все страницы);
  - похожие исполнители;
  - страницы каталогов лейблов, найденных в жанровых альбомах.
- **Новые исполнители** приходят из пяти источников: жанровые страницы, лейблы, новинки, похожие исполнители и соавторы жанровых треков.
- **Очередь не по популярности:** следующий исполнитель выбирается случайно из источников по очереди, поэтому найденные через лейбл или соавторство идут наравне с топовыми.
- **Жанр** определяется по жанру альбома. Исполнитель остаётся в каталоге, если в его дискографии есть хотя бы один трек нужных жанров. Исполнители с неизвестным жанром тоже проверяются по дискографии.
- **Все версии треков сохраняются** (live, remaster и т. д.), дубли отсекаются только по id трека.
- **Обработка успевает за обнаружением:** когда в очереди дискографий больше 500 исполнителей (`--queue-target`), поиск новых исполнителей идёт только раз в 10 задач. Исполнители, найденные раньше, обрабатываются раньше, а внутри одного запуска порядок случайный.
- **Соавторы** попадают в очередь, только если записаны на треке нужного жанра и не помечены как исполнители чужих жанров. Общие лейблы, у которых меньше 5% нужного жанра, закрываются после 2 страниц.
- **Большие дискографии почти без нужного жанра** (у исполнителя нет жанрового тега, а на первой сотне треков нужного жанра меньше 10%) откладываются, а не отбрасываются. Остальные страницы догружаются по 5 за задачу: изредка (раз в 20 задач) и после того, как опустеет основная очередь. В `status` такие исполнители показаны как «отложенные».
- **Бережная нагрузка:** пауза 0,6 с между запросами (`--delay`). При ошибках сети или сервера — повторы с нарастающей паузой до 2 мин. При ответе 429 пауза увеличивается. После 15 ошибок подряд сборщик останавливается с сохранением прогресса.
- **Надёжность:** каждая задача пишется в базу одной транзакцией, поэтому сбой не оставляет половину задачи. Объект, на котором задача упала 3 раза, помечается ошибочным и пропускается. Второй экземпляр сборщика на тот же каталог не запустится.
